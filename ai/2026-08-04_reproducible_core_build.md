## What was wrong or risky

- The previous core-fund date comparison reduced date tuples to Python hashes.
  Although used only within one process, direct sequence equality is clearer and
  removes collision and process-hash concerns.
- Existing artifact preparation validated many individual frames but did not have
  one explicit four-file schema and cross-artifact gate after CSV serialization.
  The entrypoint now reloads and revalidates the actual files before reporting
  success.
- Sentiment has intentional missing values on no-news days and before sufficient
  signal history. A blanket `dropna` or blanket no-missing assertion would be
  wrong, so allowed missing fields and the raw-news missingness relationship are
  explicit.
- The hosted loader emits informational Streamlit memory-cache warnings when run
  from plain Python. Both builds completed with exit 0.
- No stochastic portfolio or sentiment routine is currently used. The fixed seed
  is nevertheless set at entrypoint startup so future NumPy randomness cannot be
  accidental.
